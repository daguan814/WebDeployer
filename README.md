# WebDeployer
静态网页部署大师

把静态网页文件夹拖进后台，自动扫描并识别首页 HTML，立刻通过一个端口对外访问。
也可以直接丢一个文件进去当文件柜用：拿到一个直链，发给别人就能下载。

## 特点

- **零依赖**：只用 Node.js 内置模块，不需要 `npm install`，不需要 MySQL，不需要 nginx
- **单端口**：后台和所有站点共用 9090 端口，不同站点用不同路径区分
- **拖拽发布**：拖入文件夹即可，自动识别首页、自动统计体积
- **文件直链**：单个文件也能发布，直接拿到可以贴到任何地方的公网地址
- **可更新可回滚**：每次上传产生独立版本，切换是原子的，旧版本保留可回滚

## 启动

```bash
npm start                 # 默认监听 0.0.0.0:9090
PORT=9090 npm start       # 也可以显式指定
```

首次使用先设置后台密码：

```bash
npm run set-password                                  # 交互式输入（推荐）
ADMIN_PASSWORD='你的密码' npm start                     # 首次启动自动初始化
```

打开 http://localhost:9090/admin/ 即可。

## 访问方式

| 地址 | 说明 |
| --- | --- |
| `/admin/` | 后台管理（需要密码） |
| `/s/<站点路径>/` | 静态站点（公开访问，不需要密码） |
| `/s/<站点路径>/<文件>` | 单个文件的直链（公开访问，可以直接发给别人） |

## 当文件柜用

单个文件（PDF、压缩包、图片、Office 文档……）直接拖进后台就是一次发布，和网页文件夹没有区别：
每次上传都是一个新版本，直链地址不变，改错了还能回滚。

- **拿直链**：只有一个文件的站点，卡片上的「复制文件链接」一下就是那个文件的直链；
  文件多的站点点「文件直链」展开列表，每个文件都有「复制直链」和「下载」
- **直接点开**：复制的直链点开就是文件本身——图片和 PDF 会在浏览器里直接显示，压缩包之类会直接下载
- **强制下载**：在直链后面加 `?download=1`，不管什么类型浏览器都会保存文件而不是尝试打开它

目录页（不带文件名访问站点根目录）会把每个文件的「复制直链 / 下载」列出来，
适合直接把目录地址发给别人，让他们自己挑。

文件还带了 CORS 头，别的网页想直接引用这些文件也不会被浏览器拦。

> 注意：公网访问受域名解析和线路影响。如果站点挂在境内服务器上且域名没有备案，
> 境外用户可能访问不到（包括境外在线服务来抓取你的文件）。

## 密码与安全

- 密码以 scrypt 哈希存在 `data/webdeployer.db`，不落明文
- 同一 IP 连续输错 5 次即锁定：15 分钟 → 1 小时 → 4 小时 → 24 小时
- 本机 `127.0.0.1` 不参与锁定，避免把自己关在门外
- 被锁住时用 `node tools/unlock.js` 查看记录，`node tools/unlock.js` 直接清空解锁
- 登录状态是 HttpOnly Cookie，12 小时有效，活跃会自动续期

## 数据存放

```
data/
├─ webdeployer.db              # 站点清单、版本记录、会话、登录失败记录
└─ sites/
   └─ <站点路径>/
      └─ releases/<版本>/        # 每个版本一个完整目录
```

备份就是打包 `data/` 目录。

## 放到服务器上

```bash
git clone <仓库> && cd WebDeployer
ADMIN_PASSWORD='你的密码' npm start
```

只监听一个端口，安全组/防火墙放行 9090 即可。若前面挂了反向代理，设置 `TRUST_PROXY=1`，
程序才会信任 `X-Forwarded-For` 和 `X-Forwarded-Proto`。

## 用 Docker 部署（推荐放到 NAS）

```bash
cd /vol1/docker/webdeployer/app
cp .env.example .env && vi .env      # 填上后台密码
docker compose up -d --build
```

数据放在 `/vol1/docker/webdeployer/data`，容器删了重建数据都还在。
备份就是打包这个目录。

几个要点：

- **在 NAS 上 build**，别在电脑上 build 完再拷镜像，这样架构（x86/ARM）自动匹配
- `data` 目录要放在**存储池的共享目录**里，不要放系统盘，系统重装会丢
- 升级只要 `docker compose up -d --build`，容器的 `data` 卷不受影响
- 看日志 `docker logs -f webdeployer`，改密码 `docker exec -it webdeployer node tools/set-password.js`

## 开启 HTTPS

只下载一个镜像 `node:24-alpine` 就够了，HTTPS 由本服务直接提供，不需要 nginx 或 Caddy。

把证书文件夹只读挂进容器，再用两个环境变量指过去：

```yaml
    environment:
      TLS_CERT: "/certs/你的证书.pem"     # 证书（含中间证书的 fullchain 更好）
      TLS_KEY:  "/certs/你的私钥.key"
    volumes:
      - /vol2/1000/deploy/证书文档:/certs:ro
```

重启后服务就变成 `https://你的域名:9090/`。

注意事项：

- **证书是给哪个域名签的，就必须用哪个域名访问**。用 IP 访问浏览器会报证书错误。
- 打包证书（`.pfx` / `.p12`）可以用 `TLS_PFX` + `TLS_PFX_PASSPHRASE` 代替上面两个变量。
- 建议继续用 9090 端口，不要抢 443 —— 飞牛自己的网页界面大概率占着 443。
- 证书文件名或路径写错时，容器会打印明确的中文报错然后退出，日志里一眼能看到。
